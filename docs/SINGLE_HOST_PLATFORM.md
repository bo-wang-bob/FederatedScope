# 单机准确率平台

## 本架构增强训练（2026-09-10）

- 页面展示名统一为“本架构”，内部方法 ID `heterogeneous_solution` 与原算法类名保留，兼容历史记录。
- 选择“本架构 → 重新生成增强数据”：不要求已有增强缓存，预检只校验原始训练/测试特征；正式启动后用原算法完成本地统计、全局统计交换、特征增强和联邦训练。不会把基线改名冒充本架构。
- 页面可设置原样本生成数、原型生成数、每客户端每类目标样本数、协方差缩放；参数写入有效配置。每客户端训练样本数作用于增强后的训练抽样，0 使用全部。增强源参数与训练抽样分开保存。
- 新生成缓存位于本实验 `augmented_cache/`，原子写入，记录逐客户端原始样本 ID、源特征及划分版本、生成参数、输出哈希。完成后可从“复用已有增强缓存 → 增强缓存来源”选择该实验，不需再次生成。
- “服务器历史缓存”需要明确勾选来源限制确认。核验客户端完整性、配置、版本、标签、数值和哈希；存在统计时额外检查计数/均值。没有完整源样本记录的旧缓存仍标记 `legacy-metadata-only`，不证明历史生成过程没有测试泄漏。配置不符或多个不同匹配版本时拒绝运行，不静默回退。
- 原始主干特征仍必须已有且完整；本次开放的是统计式特征增强，不是下载主干、重新提取图片/文本特征。DomainNet 缺失/不匹配测试缓存的限制仍保留。
- 生成过程中可停止，只终止本实验进程；部分文件保留用于排错，失败或中断实验的缓存和模型不进入可选列表。
- 基线与本架构切换保留共享训练参数。提升验证建议同测试集、划分、种子、轮数、本地轮数、学习率、batch 和参与数；若比较相同训练计算量，还应固定每客户端样本数并核对 `trainingExposure` 中的实际样本暴露数和优化步数。同轮数本身不代表相同计算量。
- 建议比较 `final`，使用多个种子和充分训练预算；不能把单次短训或 test 择优的 `best` 当作稳定提升证据。

配对真实验收：`python scripts/platform_architecture_acceptance.py --rounds 5`；先训练 FedAvg，再重新生成并训练本架构，均使用同一冻结测试集独立评测。可用 `--source-id <已完成新生成实验ID>` 验证严格缓存复用。

本次验收：前端 29 项、后端 22 项测试通过。Office-Home/ViT 的 60 客户端按配置新生成、两轮训练及 4679 样本独立评测闭环通过；新缓存严格复用通过。五轮配对试跑（各客户端 128 样本、相同学习率/批大小/参与数/种子）的观察准确率为 FedAvg 1.6029%、本架构 1.8380%，差 0.2351 个百分点；二者均远未收敛，不作稳定提升结论。历史 MDSent/LSTM 完成兼容短训并保留来源警告。生成过程中停止测试在首客户端保存后退出，清理成功；预检不生成文件。

## 模型体验台

- 入口 `/?view=experience`，模型与测试集选择 -> 按域/类别浏览真实图片 -> 点选样本 -> 调用已保存分类器 -> 展示类别、Top-5、Softmax 分数、真实标签和耗时。错误预测正常显示，不伪造指标或热力图。
- 当前接入平台已保存的 Office-Home、Digits、DomainNet 图像模型；文本模型仍使用独立评测。短轮训练会明确提示不能代表精度达标，正式外部模型需要先核验测试索引与元数据。
- 图片只从完成任务的测试清单定位到登记数据根目录；拒绝任意路径、越界链接、样本清单和图片版本变化。预测输出模型、特征包、样本清单、当前原图哈希。
- 原图用于预览，实际输入为已有冻结特征，不进行原图端到端推理。旧缓存缺少内嵌 ID 时仍有历史逐图关联证据限制；当前图片哈希不证明历史特征重新计算来源。页面明确展示该限制。
- 单图使用原完整评测中的同一 256 样本 CPU 批次，保证近似相等 logits 的舍入口径一致。Softmax 未经校准，不视作正确概率。
- 每次预测使用自己的可停止进程和持久化任务记录，复用现有幂等、并发限制和清理逻辑；切换样本即清除旧结果。

## 参数与评测语义

- 页面“通信轮数”表示实际模型更新次数，不包含初始化轮 0；底层 `total_round_num = rounds + 1`。
- 所有客户端先完成缓存准备。每轮参与数为 0 时全部参与；否则按记录的随机种子确定性抽取客户端，每轮独立抽取。
- 本地轮数、学习率、batch size、客户端数、训练种子、数据划分种子、alpha、样本上限和评测频率均绑定到实际配置。
- Digits 的现有固定划分锁定为 60 客户端、alpha=0.1、splitSeed=42；不接受不会生效的划分参数。
- `samplesPerClient=0` 使用全部客户端原始缓存；正数启用原实现的确定性抽样（可能有放回），分布与训练样本数有记录。
- 普通算法统一禁用增强数据生成；保留各源 YAML 的 FedProx、FedProto、FedOpt、MOON 设置。旧 YAML 中部分“FedAvg”启用了生成，平台不会沿用这项误配置。
- 训练仍使用原算法和所选 GPU。所有训练期测试与独立评测统一使用 CPU float32、batch 256、2 线程，避免 CPU/GPU LSTM 近似相同 logits 在边界样本上产生不同预测。
- 总体准确率按样本加权；分域平均按域等权。Macro 指标按真值或预测中出现的类别等权。最终轮强制评测。
- `best` 基于训练期测试指标选取，不能视为无偏泛化估计；默认建议 `final`。

## 缓存与复现

- 原资源目录只读复用，不下载主干、不重复提取特征。明确选择生成模式时允许生成增强特征到本实验目录。缺失原始训练样本、测试缓存、维度/标签不匹配时明确失败。
- 可用 `FS_PLATFORM_CACHE_<GROUP大写>` 指定某组的既有训练缓存目录，`FS_PLATFORM_TEST_CACHE_<GROUP大写>` 单独指定既有测试缓存。目录写入复现记录，仍须通过样本、完整标签序列校验，不会复制覆盖原缓存。
- 部分旧测试缓存没有样本 ID：按原缓存文件命名中的模型/划分/种子、全部样本数及完整标签顺序进行绑定。此类证据弱于内嵌样本 ID，限制写入 `testProvenance`，不会宣称逐行原始来源已得到加密证明。
- 记录请求、实际解析配置、参数绑定、划分/缓存哈希、原始样本清单、运行环境、Git 提交、实际 Python 源码快照、模型、测试特征、日志和每轮参与集合。
- 预检后再次验证缓存和划分指纹。改参必须重预检。接口对未知字段、非法值、重复请求及并发冲突明确拒绝。

## 停止与恢复

- 仅根据该任务 spec 绝对路径、PID 与创建时间识别并回收进程/其子进程；不按端口、Python 名称或 GPU 号批量杀进程。
- 停止保留日志与部分产物；失败产物不进入模型库。清理未成功会阻止新任务并提供重试。
- 重启后回收遗留的本平台任务，恢复任务历史并标为中断。不会假装从缺少完整客户端优化器状态的模型继续训练；可从页面复用配置重新预检、重跑。
- 原系统、其他工作树、GPU 上的无关任务均不参与清理。
