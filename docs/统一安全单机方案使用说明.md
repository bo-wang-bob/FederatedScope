# 统一安全单机方案使用说明

## 1. 目标与边界

本方案在单台机器上模拟一个服务端和多个逻辑客户端，集中解决联邦学习中的三个问题：

- 客户端数据分布和特征空间不一致。
- 模型更新可能泄露本地训练信息。
- 恶意客户端可能污染统计量或模型更新并植入后门。

本方案不启动真实网络客户端，也不要求多机通信。隐私评估和后门攻击实验相互独立，一次运行只能选择其中一种。

## 2. 总体训练顺序

### 2.1 第一阶段：特征统计与本地扩充

1. 每个逻辑客户端读取自己的本地数据。
2. 客户端使用统一且冻结的特征提取器生成特征。
3. 客户端按类别计算原型、协方差和样本统计量。
4. 服务端接收统计量并执行第一阶段异常检测。
5. 服务端只使用通过检查的统计量计算全局类别信息。
6. 客户端接收聚合结果，在本地生成补充特征。

这一阶段用于减小跨域、标签偏斜和样本量差异造成的训练偏差。交换的是必要统计量，不交换原始图像。

### 2.2 第二阶段：正常联邦训练

1. 服务端向本轮参与客户端发送当前分类模型。
2. 客户端在原始特征和补充特征上执行本地训练。
3. 客户端根据安全模式处理待上传的模型参数。
4. 服务端在聚合前执行第二阶段异常检测。
5. 服务端聚合通过检查的客户端更新并进入下一轮。

## 3. 安全模式

### 3.1 普通模式

普通模式只执行异构解决方案，不执行隐私评估或后门攻击。它适合验证两阶段训练主链路和基础分类准确率。

配置文件：

```text
scripts/standalone_configs/heterogeneity.yaml
```

### 3.2 隐私模式

隐私模式用于评估训练过程中的信息泄露风险，可分别检查：

- 样本是否参与过目标客户端训练。
- 客户端数据是否具有某类属性。
- 是否能够根据梯度或模型变化重建训练数据。

隐私保护在客户端上传参数前执行：

1. 计算本地模型更新相对全局模型的变化量。
2. 每个客户端独立维护裁剪阈值。
3. 根据本地历史更新阈值，不与其他客户端共享裁剪状态。
4. 对更新量执行裁剪。
5. 按配置向裁剪后的更新加入高斯噪声。
6. 仅上传保护后的参数和允许公开的统计信息。

隐私评估模块只能观察服务端实际收到的保护后参数，不能绕过客户端上传保护。

相关配置：

```text
scripts/standalone_configs/privacy_protection.yaml
scripts/standalone_configs/privacy_membership_attack.yaml
scripts/standalone_configs/privacy_membership_attack_protected.yaml
scripts/standalone_configs/privacy_property_attack.yaml
scripts/standalone_configs/privacy_property_attack_protected.yaml
scripts/standalone_configs/privacy_reconstruction_attack.yaml
scripts/standalone_configs/privacy_reconstruction_attack_protected.yaml
```

### 3.3 后门模式

后门模式指定一个或多个恶意逻辑客户端，在本地训练阶段注入触发模式并尝试改变目标类别预测。该模式不会启动任何隐私攻击或隐私评估插件。

相关配置：

```text
scripts/standalone_configs/backdoor_attack.yaml
scripts/standalone_configs/backdoor_attack_defended.yaml
```

## 4. 两阶段攻击防御

攻击防御分别作用于两个位置。

### 4.1 特征统计阶段

服务端从每个客户端的类别协方差、类别原型和跨类别一致性中构造多维统计特征，通过稳健标准化和协方差距离识别明显偏离总体分布的客户端。异常客户端的统计量不会进入全局类别信息计算。

### 4.2 正常训练阶段

服务端将每个客户端上传的模型变化量转换为包含距离、方向和尺度信息的多维特征，识别异常更新，只聚合通过检查的客户端参数。

两个阶段独立配置，但防御版后门配置会同时启用，以避免恶意客户端先污染特征统计、再污染模型训练。

## 5. 模式约束

配置冻结时会检查以下约束：

- 所有安全实验必须使用单机模式。
- 后门模式不能配置隐私攻击或隐私评估插件。
- 隐私模式不能配置后门攻击。
- 隐私模式不能启用后门攻击防御聚合器。
- 普通模式不能遗留已启用的攻击配置。

违反约束时程序会在训练开始前直接报错，避免不同实验逻辑同时运行。

## 6. 运行方法

使用固定测试环境：

```bash
/root/.local/share/mamba/envs/pfedba/bin/python run.py \
  --cfg scripts/standalone_configs/heterogeneity.yaml
```

切换实验时只需替换配置路径。例如运行带保护的后门实验：

```bash
/root/.local/share/mamba/envs/pfedba/bin/python run.py \
  --cfg scripts/standalone_configs/backdoor_attack_defended.yaml
```

运行前至少检查：

- `data.root` 指向本机数据集目录。
- 预训练特征提取器路径存在，或已允许自动下载。
- `device` 对应可用设备。
- 客户端数量不超过数据划分能够支持的数量。
- 输出目录有足够磁盘空间。

### 6.1 前后端联动运行

终端一在仓库根目录启动单机控制服务：

```bash
export FEDERATEDSCOPE_DATA_ROOT=/path/to/OfficeHomeDataset_10072016
export FEDERATEDSCOPE_MODEL_PATH=/path/to/open_clip_vitb16.bin
/root/.local/share/mamba/envs/pfedba/bin/python -m \
  federatedscope.standalone_api.app --host 127.0.0.1 --port 8000
```

终端二启动前端：

```bash
cd frontend
npm install
npm run dev
```

访问 `http://127.0.0.1:5173/`。先在场景页面应用数据划分，再在实验配置页面执行预检并启动。系统会检查运行模板、四域数据、精确划分清单、数据指纹、特征模型、设备和磁盘空间；任一必需项不满足时不会创建训练进程。

应用场景后生成的清单记录每个逻辑客户端的精确训练样本，保证页面展示与训练加载一致。运行期间后端把阶段、轮次、客户端状态、隐私保护统计、防御判断和指标转换成结构化事件，页面断线重连时先读取持久化快照，再续接新事件。

## 7. 输出与检查

普通训练主要检查：

- 每轮测试准确率。
- 第一阶段有效客户端数量。
- 本地特征扩充是否完成。

隐私模式额外检查：

- 上传参数是否经过裁剪和加噪。
- 每个客户端是否维护独立阈值。
- 隐私评估是否读取服务端可见参数。

后门模式额外检查：

- 干净样本准确率。
- 触发样本攻击成功率。
- 两个阶段分别保留和过滤了哪些客户端。

## 8. 核心回归测试

```bash
/root/.local/share/mamba/envs/pfedba/bin/python -m pytest -q \
  tests/test_unified_security.py
```

核心测试不下载数据集，也不启动真实客户端。它使用小型张量和模拟对象验证训练模式、安全约束、本地加噪及两个阶段的异常过滤逻辑。
